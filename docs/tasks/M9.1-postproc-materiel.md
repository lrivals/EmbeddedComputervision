# M9.1 — Post-traitement matériel

Objectif : décodage et NMS dans le FPGA, en entiers seulement, comme 2024-zhang
[2024-zhang#013.1, #014.0, #014.2] ; l'ARM ne reçoit plus que les boîtes retenues.

### [x] T9.1.1 — Post-traitement tout entier (référence Python et C++)
- **Spec** : §8.1, §8.2, §9.4, §10.3 · **Dépend de** : T4.4, T5.3 · **Taille** : M
- **Livrables** : `python/yolo/infer/hw_postproc.py`, `cpp/golden/include/golden/hw_postproc.hpp`
  + tests
- **Acceptation** : aucun flottant entre la tête int8 et les boîtes (coins en pixels Q4,
  scores Q16, IoU par produits croisés) ; Python == C++ à l'octet sur les dumps et sur des
  têtes aléatoires ; écart de mAP à la NMS triée de référence mesuré sur VOC2007 test
- **Notes** :
  - NMS sans tri (2024-zhang) : une candidate qui recouvre une sélectionnée de meilleur
    score est rejetée ; sinon elle remplace les sélectionnées qu'elle recouvre. Ce n'est pas
    toujours le résultat de la NMS gloutonne triée (une boîte éliminée par une boîte
    elle-même remplacée ne revient pas) : écart à mesurer, pas à annuler
  - IoU > θ avec θ = p/q ⟺ (p+q)·inter > p·(a₁+a₂) : pas de division
  - pas de grille (416/S) puissance de 2 : le passage cellule → pixels est un décalage
- **Fait** : `hw_postproc.py` (coins Q4, ancres Q8, scores Q16 avec une réciproque
  ⌊2³²/Σe⌋ par cellule, 256 emplacements, débordements comptés) et `hw_postproc.hpp`
  (primitives sans allocation reprises par le noyau) ; `golden_run hwpp`. Python == C++ à
  l'octet sur les dumps v2/v3 (seuils 0,25 et 0,005) et des têtes aléatoires
  (`test_hw_postproc.py`) ; écart aux boîtes flottantes < 1 pixel Q4. Variante
  `int-hwpp` de `eval_quant.py` : mAP **55,56** contre 55,66 (−0,10, entièrement dû à la
  NMS sans tri et aux coordonnées entières ; 50 débordements sur 4 952 images, sans effet).

### [x] T9.1.2 — Noyau HLS `yolo_post`
- **Spec** : §10.3 · **Dépend de** : T9.1.1, T6.1 · **Taille** : M
- **Livrables** : `hls/kernels/postproc.cpp`, `hls/tb/tb_post.cpp`
- **Acceptation** : boîtes == golden `hw_postproc` (C-sim g++) sur les dumps et sur des têtes
  aléatoires ; cycles estimés pour les 845 candidates de Tiny-YOLOv2, rapprochés de
  0,38 ms [2024-zhang#020.3]
- **Notes** : capacité de sélection fixe (débordement signalé, jamais silencieux)
- **Fait** : `yolo_post` (descripteurs de têtes et tables dans un tableau `tab`, résultat
  [n, débordements, boîtes]) ; `tb_post` (ctest) : 1 014 cas == golden. Cycles : ≈ 1 400
  pour une image au seuil 0,25 (7 µs à 200 MHz, contre 0,38 ms chez 2024-zhang), 342 000
  dans le pire cas où les 845 cellules passent (NMS à 256 emplacements, 1 comparaison par
  cycle) — `results/postproc_hw.md`.
- **Reste** : synthèse (`make hls-synth-post`).
