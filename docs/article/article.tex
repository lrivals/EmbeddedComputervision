\begin{abstract}
We rewrite the Tiny-YOLOv2 and Tiny-YOLOv3 detectors from scratch in NumPy, without any
deep-learning library, with forward and backward passes checked by finite differences.
With the published Darknet weights, the float model reaches \chiffre{map.voc.float} \gls{map} on
\gls{voc}2007 test (\chiffre{map.voc.images} images). We fuse batch normalization, quantize
weights per channel and activations per layer to \gls{int8}, and run the network in integer
arithmetic only: the gap to the float model is \chiffre{map.voc.drop} point
(\chiffre{map.voc.int8} \gls{map}), without quantization-aware training. A C++ \gls{golden} and
a single-engine Vitis \gls{hls} accelerator reproduce the integer model byte for byte; driven by
the \gls{arm} driver over the \glslink{csim}{C-simulated} kernel, the whole test set gives
\chiffre{map.voc.identical} identical images, hence \chiffre{map.voc.csim} \gls{map}. On a Kria
KV260 at 200~MHz, the cycle model of the optimized kernel projects
\chiffre{perf.kv260.v2.ms}~ms per image, i.e.\ \chiffre{perf.kv260.v2.gops} \gls{gops} for
\chiffre{model.v2.gmacs} \gls{gmac}; the board itself has not been measured yet. Extensions
compare power-of-two weights, 4-bit quantization, integer hardware post-processing
(\chiffre{map.formats.hwpp} \gls{map}) and a streaming architecture (\chiffre{stream.w8.fps}
images/s); packing two \gls{int8} multiplications per \gls{dsp} brings the projection to
\chiffre{pack.v2.tm64.ms}~ms with the same \gls{dsp} count. The same chain runs YOLOv4-tiny on \gls{coco}
(\chiffre{map.coco.v4.ap50} \gls{ap}50 in float, \chiffre{map.coco.v4.drop} point in \gls{int8}), and
YOLOv7-tiny is being brought onto it. A dependability layer injects bit flips into the
integer model and the kernel buffers, checks every convolution with an exact int32 checksum
(\gls{abft}) down to the \gls{hls} kernel, and flags out-of-distribution inputs from the backbone
features (\gls{auroc} \chiffre{ood.norm.auroc.flir} on thermal images). Safety evidence follows:
an equivalence matrix per layer and stage, with the integer model, the \gls{golden} and the
kernel equal byte for byte and \chiffre{equiv.smt.proved} \gls{smt} obligations proved on the
scalar kernels, and a static latency bound that does not depend on the image
(\chiffre{wcet.v2.frame.ms}~ms per frame for Tiny-YOLOv2). First sweeps fine-tune
Tiny-YOLOv3 on five other datasets.

\section{Introduction and contributions}

Object detection on embedded \glspl{fpga} is usually reached through vendor toolchains: a network
trained in a deep-learning framework is quantized by a vendor tool and mapped to a
preconfigured processing unit, as with the Vitis AI \gls{dpu} used by \citet{2026-fata} on the
same board as ours. Every layer of that stack hides choices that change the result:
preprocessing, rounding, the integer approximation of the activation, the head decoding.
This work takes the opposite route and rebuilds each layer by hand, so that every number
can be traced to a line of code and checked against the stage before it.

The \gls{yolo} family predicts boxes on a grid in a single pass over the image
\cite[\#002.0]{1506.02640}; Tiny-YOLOv2 keeps one $13\times13$ output map
\cite[\#002.2]{1612.08242} and Tiny-YOLOv3 adds a second one at $26\times26$
\cite[\#004.1]{2023-zhai}. These two networks are small enough for a mid-range Zynq
UltraScale+ and are the reference workload of most \gls{fpga} papers of the \gls{base}
(Section~\ref{sec:related}). YOLOv4-tiny and YOLOv7-tiny, more accurate on \gls{coco} at a
similar cost, keep the leaky activation and the Darknet format, and test how far the same
engine goes (outside the \gls{base}).

Contributions:
\begin{enumerate}
\item \textbf{A complete chain without a learning library}: layers, losses, training,
  decoding, \gls{nms} and \gls{voc} evaluation in NumPy, each gradient checked by finite differences
  (Sections~\ref{sec:networks} and~\ref{sec:inference}).
\item \textbf{\glslink{bitexact}{Bit-exactness} from the NumPy integer model to the \gls{hls} kernel}: the integer
  model, the C++ \gls{golden} and the \glslink{csim}{C-simulated} kernel behind the \gls{arm} driver produce the
  same bytes, verified on the whole \gls{voc}2007 test set (Sections~\ref{sec:quant},
  \ref{sec:golden} and~\ref{sec:results}).
\item \textbf{One engine for v2, v3 and YOLOv4-tiny}: a single parameterized
  layer-by-layer accelerator runs the three networks from a \gls{manifest}, with route,
  \gls{groupedroute} and \gls{upsample} handled by addressing (Section~\ref{sec:hls}).
\item \textbf{Formats compared on the same model}: \gls{int8}, power-of-two weights after
  REQ-YOLO, 4-bit weights and activations, and integer post-processing, all evaluated on
  the same test set with the same protocol (Section~\ref{sec:extensions}).
\item \textbf{Dependability checks on the integer model}: fault injection, an exact \gls{abft}
  checksum per convolution in Python, in the \gls{golden} and in the \gls{hls} kernel, and an
  out-of-distribution monitor that costs a negligible share of the detector
  (Section~\ref{sec:dependability}).
\item \textbf{Safety evidence}: a model $\leftrightarrow$ circuit equivalence matrix per
  layer and stage, exhaustive operator tests, an \gls{smt} proof of the scalar kernels,
  traceability checked in \gls{ci}, and a static latency bound of the accelerator
  (Section~\ref{sec:safety}).
\item \textbf{Reproducible tooling}: \glspl{tier} of test profiles, figures, notebooks and this
  article are regenerated from the repository by \texttt{make} targets
  (Section~\ref{sec:repro}).
\end{enumerate}

State of the project at the last render: \articleetatresume{} (details in
Section~\ref{sec:limits}).

\section{Related work}\label{sec:related}

Two families of \gls{cnn} accelerators coexist on \glspl{fpga} \cite[\#004.0]{2018-venieris}. A
\emph{streaming} architecture instantiates one hardware stage per layer and pipelines
them, which gives latency and throughput but needs one \gls{bitstream} per network; SATAY keeps
all parameters on chip this way \cite[\#006.0]{2023-montgomerie-corcoran}. A \emph{single
engine} runs the layers one after the other on a systolic array or a matrix unit,
scheduled by software \cite[\#007.1]{2018-venieris}; it fits a small Zynq and serves
several networks with one \gls{bitstream}, at the price of \gls{ddr} traffic at every layer. The
\glslink{tile}{tiling} of the convolution loop nest and its \gls{roofline} analysis come from
\citet[\#009.0, \#010.2]{2015-zhang}.

Table~\ref{tab:benchmarks} lists the results of the \gls{base} (specification §10.4) next to
ours, and Figure~\ref{fig:etat_art} plots them. Most rows cannot be compared directly with
this work, for reasons the numbers alone do not show:
\begin{itemize}
\item \textbf{2024-zhang} is the only reference on the same model (Tiny-YOLOv2 416, \gls{int8},
  batch of 1). It runs on an \gls{fpga} without an \gls{arm} core, packs two multiplications per \gls{dsp}
  \cite[\#008.0]{2024-zhang} and includes hardware post-processing
  \cite[\#013.1]{2024-zhang}.
\item \textbf{2026-fata} runs on the same KV260, but with a preconfigured \gls{dpu}, a
  YOLOv3-tiny pruned at 70\,\% and \gls{qat} \cite[\#014.4, \#015.0]{2026-fata}: pruning divides the \glspl{mac}
  by about three, so images per second do not convert.
\item \textbf{2023-zhai} uses \gls{int16} and a pruned network on a vehicle dataset; only the
  order of magnitude of its \gls{gops} compares \cite[\#002.0]{2023-zhai}.
\item \textbf{2019-ding} (REQ-YOLO) uses FFT-based convolutions and power-of-two weights
  chosen by \gls{admm} \cite[\#008.1, \#009.4]{2019-ding}, on another architecture.
\item \textbf{2025-kim} is a slow functional prototype of the full YOLOv2 on a Zybo, with
  decoding on the \gls{arm} \cite[\#026.0]{2025-kim}: not a performance reference.
\item Power is reported with different perimeters (chip estimate, board, unspecified);
  ours will be measured both on the chip (\texttt{report\_power}) and on the \gls{som} (INA260).
\end{itemize}

\section{Networks and NumPy building blocks}\label{sec:networks}

Tiny-YOLOv2 is a stack of nine $3\times3$ convolutions with batch normalization and leaky
\gls{relu}, six max-pooling layers (the last one $2\times2$ with stride 1) and a linear
$1\times1$ head with $5\times(5+C)$ filters; Tiny-YOLOv3 adds a second head at
$26\times26$ fed by an \gls{upsample} and a route that concatenates an earlier map
\cite[\#005.0]{1804.02767}, \cite[\#016.2]{2023-zhai}. Counted by \texttt{make count-macs}
from the network descriptions, Tiny-YOLOv2 \gls{voc} has \chiffre{model.v2.mparams}~M parameters
and \chiffre{model.v2.gmacs} \gls{gmac} at $416\times416$, in agreement with the count of
CoDeNet \cite[\#025.0]{2006.08357}; Tiny-YOLOv3 \gls{voc} has \chiffre{model.v3.mparams}~M
parameters and \chiffre{model.v3.gmacs} \gls{gmac} (Figures~\ref{fig:graphe/graphe_tiny-yolov2-voc}
and~\ref{fig:fiche/fiche_tiny-yolov2-voc}).

\articlefig{graphe/graphe_tiny-yolov2-voc}
\articlefig{fiche/fiche_tiny-yolov2-voc}

YOLOv4-tiny (\texttt{tiny-yolov4-coco}, outside the \gls{base}) replaces the plain backbone by
\gls{csp} blocks: a \emph{\gls{groupedroute}} takes the second half of the channels of a map, and the
heads rescale the box centres by \texttt{scale\_x\_y}. It has \chiffre{model.v4.mparams}~M
parameters and \chiffre{model.v4.gmacs} \gls{gmac} (Figure~\ref{fig:graphe/graphe_tiny-yolov4-coco}).
The \gls{groupedroute} is one more addressing mode of the engine: it reads a channel range of an
existing buffer, so it costs no compute and no copy. YOLOv7-tiny
(\texttt{tiny-yolov7-coco}, \chiffre{model.v7.mparams}~M parameters,
\chiffre{model.v7.gmacs} \gls{gmac}) adds \gls{elan} blocks, whose concatenations have four sources, and a
spatial pyramid pooling with stride-1 max pools of $5\times5$, $9\times9$ and
$13\times13$. The export rewrites the two larger pools as chained $5\times5$ pools and
copies the pooled input by an identity $1\times1$ convolution; this network is work in
progress (float, \gls{calibration} and export done; its float \gls{coco} accuracy is in
\repo{results/map\_coco.md}, the integer one is not measured yet). YOLOv5n and
YOLOv8n (Ultralytics, \gls{silu} activation, \glslink{anchor}{anchor-free} head for v8n, outside the \gls{base}) are read
from their checkpoints without PyTorch: a reader of the pickle format and the network
rebuilt from its YAML description give a trainable NumPy YOLOv5n equal to the reference to
about $10^{-14}$ (\ms{M33}).

\articlefig{graphe/graphe_tiny-yolov4-coco}

Every layer exposes the same interface, \texttt{forward(x) -> (y, cache)} and
\texttt{backward(dy, cache) -> (dx, grads)}. The convolution exists in a naive version,
kept as the test reference, and an \gls{im2col} version used for training; both agree to
$10^{-12}$ (Figure~\ref{fig:convolution}). The weight gradient is the correlation of the
output gradient with the input \cite[\#013.0]{2202.10935}. Each layer passes a gradient
check with centered differences in float64, using the max norm over the tensor so that a
gradient that happens to be small is not drowned in rounding noise (outside the \gls{base};
Figure~\ref{fig:retropropagation}).

\articlefig{convolution}
\articlefig{retropropagation}

The loss is the YOLOv3 one: direct regression of the box offsets, whose gradient is
``ground truth minus prediction'' \cite[\#003.0]{1804.02767}, logistic \gls{objectness} with an
\emph{ignore} rule for predictions that overlap a ground truth without being responsible
for it \cite[\#003.1]{1804.02767}, and multi-label binary cross-entropy for the classes
\cite[\#004.0]{1804.02767}. Targets are assigned to the best \gls{anchor} by \gls{iou} of the shapes;
\glspl{anchor} come from k-means with the distance $1-\mathrm{IoU}$ \cite[\#002.4]{1612.08242}.
The training loop (\gls{sgd}, \gls{burnin}, multi-scale inputs \cite[\#003.3]{1612.08242}) overfits a
single image, which validates targets, loss and optimizer together
(Figure~\ref{fig:perte}).

\section{Inference and evaluation}\label{sec:inference}

Inference decodes each head with the YOLOv2 parameterization \cite[\#003.1]{1612.08242},
filters predictions by confidence, then applies a per-class \gls{nms} at \gls{iou} 0.45. Evaluation
follows the \gls{voc}2007 protocol: 11-point \gls{ap}, \texttt{difficult} objects ignored, confidence
threshold 0.005; our implementation matches the official devkit to $10^{-12}$
(\repo{python/tests/test\_metrics.py}).

With the published Darknet weights the reference \gls{map} is \chiffre{map.voc.float}, against
\chiffre{map.voc.darknet} published by Darknet. Preprocessing explains most of what
separates the variants (Table~\ref{tab:float}): these weights were trained by the Darknet
of the YOLOv2 era, which resizes the image to a square without keeping its aspect ratio.
A \gls{letterbox}, as in our training pipeline, shrinks and distorts the objects differently
than in training and loses about two points; reproducing the Darknet bilinear
interpolation instead of Pillow's barely changes the result. The reference therefore uses
the direct resize (\texttt{stretch}), which is also the simplest one to reproduce on
hardware. The remaining gap to the published figure is below the one-point tolerance of
the project; its plausible causes (JPEG decoder, details of the Darknet evaluation loop)
are not measured. Figures~\ref{fig:pr/pr_variantes} and~\ref{fig:nms_map} show the
precision-recall curves and the evaluation steps.

\section{INT8 quantization}\label{sec:quant}

The integer model follows the usual post-training quantization path
\cite[\#008.0]{2607.13106}. Batch normalization is first folded into the convolution
weights and biases \cite[\#039.0]{2023-zhai}. Weights are quantized symmetrically per
output channel; activations per layer, with scales calibrated on 500 \gls{voc}2007 trainval
images (percentile \texttt{p99.99} of $|x|$, chosen by a mean-squared-error criterion).
Each convolution accumulates in 32 bits and \glslink{requant}{requantizes} its output with an integer
multiplier $M_0$ and a shift, so that no floating point remains in the network (outside
the \gls{base}). The leaky \gls{relu} slope becomes $13/128$, computed as $(13y+64)\gg7$: rounding
instead of flooring avoids a bias of half a step on every negative value, which
accumulates from layer to layer. The heads are decoded by 256-entry tables for the sigmoid
and the exponential, as in 2024-zhang \cite[\#014.0]{2024-zhang}; their input step is
$1/8$, because at $1/16$ the class logits of Tiny-YOLOv2 saturate and the softmax
flattens (Figures~\ref{fig:quantification}, \ref{fig:entier}
and~\ref{fig:calibration/calibration_tiny-yolov2-voc}).

\articlefig{quantification}
\articlefig{entier}

The integer model stays within \chiffre{map.voc.drop} point of the float model with the
reference preprocessing (Table~\ref{tab:int8}), below the one-point target:
quantization-aware training is not needed. Quantizing one layer at a time on a subset of

\section{Golden C++ model and verification chain}\label{sec:golden}

The quantized network is exported as a \gls{manifest} and binary blobs
(\texttt{model/<net>/}), with the integer activations of every layer on a few images as
\glspl{dump}. A C++ \gls{golden} reads the same export and runs the network \emph{as the hardware
will}: \glslink{tile}{tiled} convolution with fixed-size buffers, output stage with bias, \gls{requant},
leaky and fused max pooling, route by addressing. It is the testbench of the \gls{hls} stage.

Equality is checked at every hand-over (Figure~\ref{fig:chaine_verif}).
\texttt{make golden-check} runs the \gls{golden} on \chiffre{verif.dumps} \glspl{dump} (three
images per quantized network) and compares every layer to the Python \glspl{dump}; the \gls{hls} kernel
in \gls{csim} is compared to the \gls{golden} layer by layer (\texttt{make csim-gcc});
the \gls{arm} driver, built with a simulation backend that calls the \glslink{csim}{C-simulated} kernel, is
compared to the \gls{golden} on the final heads (\texttt{make sw-sim}). The integer
post-processing kernel of Section~\ref{sec:extensions} is compared to its golden mirror on
\chiffre{verif.hwpp.cases} cases. All of these run in \texttt{make ci} on every commit, on
a synthetic export when the Darknet weights are absent.

\section{HLS accelerator and SoC integration}\label{sec:hls}

The board was chosen with a \gls{roofline} explorer before writing any \gls{hls} (\gls{adr} 0003): the Kria
KV260 offers, at the same price, about six times the \gls{roofline} performance of a Zynq-7020
board for these networks. The accelerator is a single layer-by-layer engine
(Figure~\ref{fig:moteur}): the convolution loop nest is \glslink{tile}{tiled} over output channels, input
channels, rows and columns \cite[\#010.2]{2015-zhang}, with $T_m=32$, $T_n=24$ and
$T_r=T_c=13$, i.e.\ 768 \glspl{mac} per cycle at 200~MHz (Figure~\ref{fig:tuilage}). One engine
runs every layer of both networks; \gls{upsample} and route need no compute, they change the
read address of the next layer.

\articlefig{moteur}
\articlefig{tuilage}

The \gls{arm} side loads the \gls{manifest} and the blobs in contiguous memory, programs the AXI-Lite
registers of the kernel layer after layer and waits for its interrupt
(Figure~\ref{fig:soc}). The block design, the device-tree overlay and the firmware
packaging are scripted (\texttt{make vivado-build}, \texttt{make fpga-firmware}) but have
not run yet: Vivado and Vitis are not installed on the development machine. Everything
above the hardware runs on the PC through the simulation backend.

\articlefig{soc}

A cycle model in Python (\repo{tools/perf\_model.py}) reproduces the cycle counters of
the \glslink{csim}{C-simulated} kernel exactly, layer by layer (\texttt{make perf-model} checks it in \gls{ci}).
It shows where the first kernel (\ms{M6}) lost its time: with 8-bit memory ports it spent most
of its cycles outside the \gls{mac} loop, waiting for its ports and its output stage, and its
projection was \chiffre{perf.kv260.m6.ms}~ms per image. The optimization cascade of
milestone \ms{M10} (Table~\ref{tab:cascade}, Figure~\ref{fig:cascade_m10}) widens the ports to
64 bits, loads only the valid input channels, \glslink{requant}{requantizes} eight channels per cycle, folds
the first layer onto the input lanes and uses $14\times14$ \glspl{tile} for the pooled
convolutions; each step is \glslink{csim}{C-sim} equal to the \gls{golden}. The current kernel projects
\chiffre{perf.kv260.v2.ms}~ms, against a compute bound of \chiffre{perf.kv260.bound.ms}~ms
and a \gls{roofline} point of \chiffre{perf.kv260.roofline.ms}~ms
(Figures~\ref{fig:roofline_couches/roofline_couches_kv260} and~\ref{fig:cycles_couches}).

\paragraph{Two INT8 multiplications per DSP.} The compute bound only falls if the
multiplications per cycle rise. As in 2024-zhang \cite[\#008.0]{2024-zhang}, the weights of
two output channels that share an input are packed into the 27-bit port of a \gls{dsp}48E2,
$A = w_a 2^{18} + w_b$, and one product gives both (Figure~\ref{fig:dsp_packing}). The low
lane stays exact for a sum of eight products under the contract of the integer model
(weights and inputs within $\pm127$), so the 24-lane adder tree is cut into three groups of
eight, each unpacked to int32. Only the multiplication changes: the \glslink{csim}{C-simulated} kernel equals
the \gls{golden} byte for byte on every testbench, and its cycles are unchanged. With the same
\glspl{tile}, packing frees half of the \glspl{dsp}; with $T_m=64$ on the same \glspl{dsp} it projects
\chiffre{pack.v2.tm64.ms}~ms for Tiny-YOLOv2, but doubles the weight registers beyond the
flip-flops of the board unless they move to \gls{lutram}, and $T_n=32$ gives
\chiffre{pack.v2.tn32.ms}~ms within the budget (Table~\ref{tab:pack},
Figure~\ref{fig:pack_options}). The YOLOv4-tiny projection with the current kernel is
\chiffre{perf.kv260.v4.ms}~ms (Table~\ref{tab:perf}).

\section{Extensions}\label{sec:extensions}

\paragraph{Hardware post-processing.} Following 2024-zhang
\cite[\#013.1, \#014.0]{2024-zhang}, a separate \gls{hls} kernel decodes the heads and runs the
\gls{nms} in integers only: the \gls{objectness} threshold is applied to the integer logit, the
softmax uses one reciprocal per cell, box corners are Q4 pixels, the \gls{iou} test becomes an
integer inequality, and the \gls{nms} keeps 256 slots in stream order without sorting. This \gls{nms}
does not always give the result of the sorted one (a chain of three overlapping boxes
keeps only one); on the test set the integer post-processing reaches
\chiffre{map.formats.hwpp} \gls{map} (Figure~\ref{fig:hw_postproc}). The kernel equals its
golden mirror in \gls{csim}; its synthesis is pending.

\articlefig{hw_postproc}

\paragraph{Power-of-two weights (REQ-YOLO).} We reproduce the ``mixed powers of two''
levels of 2019-ding \cite[\#008.1]{2019-ding}: each weight is a sum of at most two powers
of two, so a multiplication becomes two shifts and an addition, and the engine needs no
\gls{dsp} for its \glspl{mac} (estimate). The direct projection of the trained weights gives
\chiffre{map.formats.mixed6} \gls{map}, against \chiffre{map.formats.uniform6} for uniform 6-bit
levels. The \gls{admm} fine-tuning \cite[\#009.1]{2019-ding} \emph{did not converge}: the
residual between the weights and their projection grew instead of vanishing, the
detection loss rose, and the result, \chiffre{map.formats.admm} \gls{map}, is worse than the
projection alone. The likely causes (fine-tuning without \gls{bn}, small batches, a penalty too
weak) are not verified. The power-of-two variant of the \gls{pe} is \glslink{csim}{C-sim} equal to the \gls{golden}.

\paragraph{4-bit weights and activations.} With 4-bit weights per channel and 4-bit
activations on power-of-two steps \cite[\#006.0]{2024-yan}, keeping the input and the head
on 8 bits, post-training quantization collapses to \chiffre{map.formats.w4a4.ptq} \gls{map}. A
short quantization-aware training (600 iterations, a fraction of an epoch, on \gls{cpu})
recovers part of it, to \chiffre{map.formats.w4a4.qat} \gls{map}; the loss was still decreasing,
so a longer run should do better. The 4-bit export is reproduced byte for byte by the
\gls{golden} and the \glslink{csim}{C-simulated} kernel. Table~\ref{tab:formats} and
Figure~\ref{fig:map_formats} sum up the formats.

\texttt{quant\_4bits.md}, \texttt{postproc\_hw.md}).}

\paragraph{Streaming architecture.} The second family of Section~\ref{sec:related}
\cite[\#004.0]{2018-venieris} is planned with one stage per convolution and line buffers
\cite[\#011.0]{2023-montgomerie-corcoran}. The weights of Tiny-YOLOv2 do not fit on the
chip of the KV260, so the plan is hybrid: the small layers stream with their weights on
chip, the two largest read theirs from \gls{ddr} once per image. The resource model estimates
\chiffre{stream.w8.fps} images/s with \chiffre{stream.w8.dsp} \glspl{dsp}, at a latency of
\chiffre{stream.w8.latency}~ms, and \chiffre{stream.w4.fps} images/s with 4-bit weights
(Figure~\ref{fig:streaming}). The streaming kernel equals the \gls{golden} in \gls{csim}, stage
by stage; these figures are estimates until synthesis.

\section{Dependability}\label{sec:dependability}

The \gls{bitexact} integer model is a fault-free reference: any difference in its output is caused
by an injected fault. This section is engineering outside the \gls{base}.

\paragraph{Fault injection.} An injector flips bits in the \gls{int8} weights, the int32 biases, the
\gls{int8} activations and the int32 accumulator of a chosen layer, either one given bit or at random
with a bit error rate, or holds them stuck at a value; every run is seeded, and with no fault the
output equals the integer model exactly. A campaign tool sweeps the error rate, the layer and the
bit position against the \gls{map}. Only a \gls{smokerun} has been made so far; the full grids are to run.

\paragraph{Exact checksum (ABFT).} The sum of the output channels of a convolution equals the
convolution of its input by the sum of its filters. Before \gls{requant} everything is an
integer, so the check holds exactly modulo $2^{32}$: no tolerance and no false alarm. The
summed filter and bias are exported with each layer, and the check runs in the integer model,
in the \gls{golden} and in the \gls{hls} kernel. The kernel computes the checksum as one more
output lane in the same pipelined loop and compares it in the \gls{requant} pass; the
failing pixels go to a status register read by the \gls{arm} driver. Without fault, every
\gls{bitexact} test passes with no \gls{abft} error (\chiffre{abft.hls.layers} layers of the four
exports, \chiffre{abft.hls.outputs} layer outputs of the network test bench, in \gls{csim}),
and every injected accumulator fault is detected. The cost of the lane waits for synthesis.

\paragraph{Faults in the kernel buffers.} A fault hook of the \gls{csim}, absent from the
synthesis, flips one bit per kernel run in an on-chip buffer of the convolution: input \gls{tile},
weights, int32 accumulators, \glslink{requant}{requantized} \gls{tile} or checksum lane. A Python reference maps each
buffer address back to its tensor element through the lane mapping of the kernel and
recomputes the outputs of the \gls{tile}: the faulty outputs match it byte for byte, and the
outputs outside the \gls{tile} equal the fault-free \gls{dump}.

\paragraph{Out-of-distribution monitor.} The monitor reads the \gls{int8} output of the last backbone
layer of Tiny-YOLOv2, which the accelerator already writes, and scores each image on the \gls{arm}.
Dark (ExDark) and thermal (\gls{flir}) images give \emph{weaker} features than \gls{voc}: they fall inside
the shell on which in-domain features lie, so a raw distance score is lower out of domain. The
monitor therefore uses the \gls{typicality} of the score, its distance to the median on held-out
\gls{voc} images in either direction. The plain norm of the pooled features is the best score
(\gls{auroc} \chiffre{ood.norm.auroc.exdark} on low light, \chiffre{ood.norm.auroc.flir} on thermal),
ahead of a Mahalanobis distance and of a NumPy autoencoder that costs ten times more
(Table~\ref{tab:ood}). It is a domain alarm, not a per-image predictor of accuracy.

\section{Safety evidence}\label{sec:safety}

Dependability detects faults at run time; this section collects the design-time evidence that
the circuit computes the model, and how long it may take. It is engineering outside the \gls{base}.

\paragraph{Model $\leftrightarrow$ circuit equivalence.} Each hand-over of the chain is
qualified at one of three levels: \emph{\gls{pointwise}} (same output), \emph{\gls{boundedprox}}
(a measured bound on the gap) or \emph{statistical} (same task metric). The float model and
its \glslink{fakequant}{fake-quantized} copy differ by a few \gls{lsb} of the layer scale, which accumulate through the
layers; the statistical gap of Section~\ref{sec:quant} is the one that counts. From the
\glslink{fakequant}{fake-quantized} model to the integer model, the only difference is the \gls{requant} by an
integer multiplier and shift and the rounded leaky activation: at most one \gls{lsb} per layer.
From the integer model on, the \gls{golden} and the \glslink{csim}{C-simulated} kernel produce the same
byte for every layer output (Table~\ref{tab:equiv}). This \gls{pointwise} level rests on three
further pieces of evidence: exhaustive and boundary tests of the operators in Python, C++
and \gls{hls}, which found and fixed an int32 overflow of the golden leaky; a proof with the z3
\gls{smt} solver of the \gls{requant}, leaky and clipping kernels for every layer
(\chiffre{equiv.smt.proved} obligations, no int32 overflow of the accumulator); and a
per-layer traceability table checked in \texttt{make ci}. The integer post-processing equals
its golden mirror and keeps its capacity and overflow properties, but its unsorted \gls{nms}
depends on the order of the cells. The \gls{cosim} and board rows wait for Vitis and the
KV260.

\begin{table}[htbp]
\caption{Equivalence per stage on 20 images per network (\repo{results/equivalence.md}):
gaps in \gls{lsb} of the layer output scale, then the level of the later stages. The \gls{cosim}
and board stages are pending.}
\label{tab:equiv}
\footnotesize\articletable{equiv.table}
\end{table}

\paragraph{A latency bound independent of the image.} The engine runs a fixed schedule of
layer descriptors: every loop bound comes from a descriptor field or a \gls{tile} constant, and
activations and weights are never a loop or branch condition. The cycle count of a layer is
therefore a function of its shape only. The static bound gives up every overlap of the
\gls{pingpong} schedule and adds the \gls{ddr} traffic at the effective bandwidth of the board and an
assumed \gls{burst} latency per transfer phase. For Tiny-YOLOv2, it gives
\chiffre{wcet.v2.acc.ms}~ms for the accelerator, against \chiffre{perf.kv260.v2.ms}~ms for
the overlapped cycle model. The post-processing is the data-dependent part: bounded by its
256 slots and by the candidates that can pass the threshold, it brings the frame bound to
\chiffre{wcet.v2.frame.ms}~ms, hence a \gls{watchdog} of \chiffre{wcet.v2.watchdog.ms}~ms.
Adversarial inputs in \gls{csim} stay under the bound. On the sigmoid heads of
Tiny-YOLOv3 and YOLOv4-tiny, the uncapped \gls{nms} dominates the worst case: a demonstrable
bound there needs a cap on the candidates. The \gls{burst} latency and the end-to-end latency on
the board remain to be measured.

\section{Limitations and future work}\label{sec:limits}

The main limitation is that no number of this article has been measured on the board. The
KV260, Vivado and Vitis are not available yet (milestones \ms{M6} to \ms{M8}): performance is a
cycle-model projection, resources are estimates, and the \gls{fpga} \gls{map} is a \gls{csim}. The
keys still in that state are listed below; milestone task \ms{T17.19} switches them to
measurements and rewrites the abstract, Section~\ref{sec:results} and this section.

\articlestatuslist

Other limits: the power-of-two \gls{admm} did not converge and the 4-bit \gls{qat} ran for a fraction
of an epoch (Section~\ref{sec:extensions}); the training from scratch in NumPy
(fine-tuning on \gls{voc}, \ms{M2}) is not finished, so the reference \gls{map} uses the published Darknet
weights; the datasets beyond \gls{voc} have only been explored at \gls{tier} R
(Section~\ref{sec:beyond}). YOLOv4-tiny still needs its full C-simulation pass on \gls{coco} and
quantization-aware training to come within one point. YOLOv7-tiny, YOLOv5n and YOLOv8n
have their float \gls{coco} accuracy (\repo{results/map\_coco.md}) and their training recipes
in NumPy, but no integer model yet (\ms{M26}, \ms{M33} to \ms{M35}). The fault campaign has
only run as a \glslink{smokerun}{smoke test}, and the \gls{abft} lane of the kernel is not
synthesized. The equivalence evidence and the
latency bound of Section~\ref{sec:safety} stop at the \gls{csim}: the \gls{cosim} and
board rows, the measured \gls{burst} latency and the latency distribution on the board are
pending. The person-detection safety metrics (\ms{M27}) are measured on the industrial
PREWID set only, and the runtime monitors (\ms{M29}) wait for them on CrowdHuman, whose data
is not on the PC; the assurance case (\ms{M31}) is written on the results present today and
